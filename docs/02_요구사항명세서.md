# JobFit 요구사항 명세서

| ID | 기능 | 요구사항 | 입력 | 출력/동작 | 우선순위 | 검증 |
|---|---|---|---|---|---|---|
| FR-01 | 공고 검색 | 키워드(제목·기업명), 기술, 출처, 등급, 유명기업만 조건으로 페이징 검색한다. 한 페이지 최대 100건 | `keyword, skill, source, tier, famousOnly, page, size` | 공고 요약 목록 + 총 건수 | 필수 | ApiIntegrationTest |
| FR-02 | 공고 상세 | 공고 1건의 본문·기술·원문 링크를 보여준다. 없으면 404 | `id` | 상세 | 필수 | 통합 테스트 |
| FR-03 | 기술 통계 | 기술별 요구 공고 수를 내림차순으로 집계한다. 결과는 캐시한다 | `famousOnly` | `[name, category, count]` | 필수 | 통합 테스트 |
| FR-04 | 회원 | 이메일·비밀번호(8~64자)·닉네임으로 가입, 로그인 시 JWT 발급(만료 120분). 이메일 중복은 409, 로그인 실패는 이메일 존재 여부와 무관하게 동일 메시지 401 | 가입/로그인 요청 | 토큰 | 필수 | 통합 테스트 |
| FR-05 | 보유 기술 | 사전에 있는 기술만 등록(최대 50). 사전에 없으면 400. 전체 교체 방식 | 기술명 목록 | 저장된 목록 | 필수 | 통합 테스트 |
| FR-06 | 적합도 | 적합도(0~100) = 공고 요구 기술 중 내가 가진 비율. 상위 20건, 일치/부족 기술 표시 | `famousOnly` | 매칭 결과 | 필수 | 단위+통합 |
| FR-07 | 관심 공고 | 담기/해제/목록. 같은 요청을 반복해도 결과가 같다(멱등) | `postingId` | 204 / 목록 | 선택 | 통합 테스트 |
| FR-08 | AI 질문 | 질문을 AI 서비스(RAG)에 전달해 답과 근거 공고를 받는다. AI 서비스 실패 시 키워드 검색 결과로 대체하고 `fallback=true` 표시. 질의 이력 저장 | `question(≤500), famousOnly` | 답변, 출처 목록 | 선택 | 대체 경로 통합 테스트 + 실제 연동 수동 확인 |
| FR-09 | 공고 적재 | 최초 기동 시 수집 JSON을 적재한다. 이미 데이터가 있으면 건너뛰고 URL 중복은 무시 | seed json | DB 적재 | 필수 | 기동 로그 |

## 인증 규칙

- `/api/me/**` 는 로그인 필요(없거나 위조·만료 토큰 → 401). 그 외 API는 공개.
- 비밀번호는 BCrypt 해시로만 저장. CORS는 설정한 오리진만 허용.

## 오류 응답 형식

`{ "code": "INVALID_INPUT | BAD_REQUEST | LOGIN_FAILED | NOT_FOUND | DUPLICATE", "message": "..." }`

## 미구현·제한 (명시)

- 수집 자동 스케줄러, 운영자 화면은 없다(수집은 스크립트 1회 실행).
- AI 서비스는 BM25 검색 + 공고 필드로 만든 정형 답변이다. 로컬 임베딩 모델(embeddinggemma)이 개발 PC에서 비정상 종료되어 의미 검색은 쓰지 못했고,
  로컬 3B 생성 모델은 컨텍스트를 되풀이해 기본값에서 끄고 `JOBFIT_USE_LLM=1` 옵션으로만 쓴다.
- 백엔드는 AI 서비스 없이도 동작한다(키워드 검색 대체 응답).
