# JobFit 요구사항 분석서

작성일 2026-11-12 · 버전 1.0

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 목적 | 신입 개발자가 "인지도 있는 기업의 신입 공고"만 모아 보고, 공고가 요구하는 기술과 내 기술을 비교해 부족한 기술을 파악한다 |
| 배경 | 취업 포털 3곳(사람인·잡코리아·워크넷)의 신입 개발 공고는 헤드헌팅·파견·이름 모를 기업 공고가 섞여 있어 선별 비용이 크다 |
| 사용자 | 신입 개발자 취업 준비생 |
| 데이터 | 2026-11-12 수집 1,097건 → 중복·헤드헌팅/파견 제외 후 1,059건 (유명기업 99건 / 그 외 960건) |

## 2. 공고 분석에서 도출한 요구 기술

유명기업 신입 가능 공고의 상세 요강에서 확인한 기술 요구(공고 원문 기준).

| 기업·직무 | 요구 기술 |
|---|---|
| 카카오페이 서버 개발자 | Kotlin, Spring Boot, MySQL, Redis, 대용량 처리 (※ 1년 이상 경력 명시) |
| 캐시워크(넛지헬스케어) 백엔드 인턴 | Nest.js/Express, REST·GraphQL, MySQL·Redis·DynamoDB, AWS, 쿼리·인덱스·캐시 개선 |
| 스틸리언 Frontend/Backend | Java·Python, Spring Boot·FastAPI, MySQL·PostgreSQL, React·TypeScript, Docker·AWS·GitHub Actions |
| 다날 AI 개발자 | Python, LLM·RAG(Vector DB·리랭킹), PyTorch, Git, Linux |
| NHN 클라우드 QA | Java·Python, REST API, Selenium·Playwright, Jenkins·GitHub Actions |
| 실리콘투 웹 개발자 | 웹·SQL 기초, .NET 또는 Java·Python·TS (신입은 프로젝트 경험으로 지원) |

**공통 패턴**: Java/Kotlin + Spring Boot, RDB(MySQL) + Redis 캐시, REST API, Docker·CI, Git. AI 직군은 Python + RAG/LLM.
→ 본 프로젝트는 이 공통 스택(Spring Boot·JPA·MySQL·Redis·JWT·Docker)과 RAG를 한 서비스에서 보여주도록 설계했다.

## 3. 이해관계자·사용자 유형

| 유형 | 설명 |
|---|---|
| 비회원 | 공고 검색·상세, 기술 통계, AI 질문 |
| 회원 | 보유 기술 등록, 적합도 매칭, 관심 공고 |
| 운영자(수집 담당) | 수집 스크립트 실행, 시드 갱신 (현 버전은 배치 스크립트, 화면 없음) |

## 4. 기능 요구사항 요약 (상세는 02 명세서)

- FR-01 공고 검색/필터 · FR-02 공고 상세 · FR-03 기술 통계 · FR-04 회원가입/로그인
- FR-05 보유 기술 등록 · FR-06 적합도 매칭 · FR-07 관심 공고 · FR-08 AI 질문(RAG) · FR-09 공고 적재(시드)

## 5. 비기능 요구사항

| 구분 | 요구 | 현재 상태 |
|---|---|---|
| 보안 | 비밀번호 BCrypt, JWT 인증, 로그인 실패 메시지 통일 | 구현·테스트 |
| 가용성 | AI 서비스 장애 시에도 질의 응답 유지(키워드 검색 대체) | 구현·테스트 |
| 성능 | 무거운 집계(기술 통계)는 캐시 | 구현(prod: Redis, local: 인메모리) — **부하 측정은 하지 않음** |
| 이식성 | 설치 없이 실행(H2) / 운영 프로필(MySQL+Redis) | 구현 (prod 프로필은 이 PC에서 실행 검증 못 함) |
| 정확성 | 기술 추출 오탐 최소화(Java ≠ JavaScript) | 사전+정규식, 단위 테스트 |

## 6. 제약·가정·한계 (솔직하게)

1. 데이터는 3개 사이트에서 검색어별 **상위 결과만** 수집했으며 전수가 아니다.
2. "유명기업"은 분석자가 정한 목록(주관적 기준)이다. "이름 모를 기업"은 "목록에 없음"일 뿐 허위·유령회사 판정이 아니다.
3. AI 생성 공고·허위·과장·페이퍼컴퍼니 여부는 목록 정보만으로 **확정할 수 없다**. 엑셀의 "의심 신호"(제목 문구, 반복 게시, 상시채용, 법인 표기 없음)는 참고 지표다. 지원 전 DART·국민연금 가입자 수 등으로 확인이 필요하다.
4. 기술 추출은 상세 본문을 읽은 19건과 제목·직무 키워드 기준이며, 나머지 공고의 기술은 불완전하다.
5. 취업 포털 약관은 자동 수집을 제한할 수 있다. 공개 배포·상업 이용 전 약관과 robots 정책 확인이 필요하다.
